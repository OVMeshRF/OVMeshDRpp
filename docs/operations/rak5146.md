# RAK5146 USB/LBT setup

The experimental adapter supports one or two **US915 RAK5146 USB/LBT** concentrators for sampled RSSI scanning across the supplied range. Packet reception, preset/key setup and classification are disabled and hidden in the spectrum-only desktop. The retained decoder backend is for future development. RAK does not supply IQ, a waterfall or continuous FFT occupancy.

## Platform and build status

The bundled receive-only worker builds on macOS and Linux by default when its platform requirements are present (`OVMESH_ENABLE_RAK5146=ON`). Linux requires the descriptor-isolation function checked by CMake; glibc 2.34 or later provides it. The backend is unavailable on Windows and other unsupported platforms. A disabled worker does not disable HackRF or RTL-SDR.

Hardware validation has used macOS. Linux implementation and synthetic tests do not establish Linux live USB qualification. Follow the [normal build instructions](deployment.md); keep the generated worker alongside the installed CLI or desktop executable as the build/install rules arrange. Do not replace it with a downloaded unreviewed helper. The application's availability label describes the build, not whether a connected board is usable.

## Setup

1. Stop reception. If a survey is already selected, choose **New** before switching to **RAK5146 USB/LBT** in the receiver dropdown. New preserves the previous saved file; memory-only results require discard confirmation.
2. Open **Settings > RAK concentrators**. Check **USB candidates found**, use **Refresh USB candidates** after plugging in or moving a board, and set **Number of boards** to One or Two. The candidate count is a metadata inventory, not a count of verified or selected RAK boards; refreshing does not open serial ports.
3. Explicitly select each known concentrator. The `0483:5740` STM32 USB identifier is generic and does not prove that an arbitrary device is a RAK. Duplicate or missing identities are rejected. The app does not automatically try every candidate or substitute an unrelated serial port.
4. Review center/span/Offset. Defaults select the full 902–928 MHz nominal range. Corrected hardware edges must remain inside that range. Offset is an operator correction, not a power calibration.
5. Packet profiles and keys are not used in this desktop build; remembered profiles cannot enable packet reception.
6. Enable **Scan RF energy** to sweep the range with 2,000 samples per scan. Choose a step of 25–1,000 kHz; the nominal filter is 234.3 kHz. Two boards split the assigned scan centers.
7. Enable recording and GPS as needed, then choose **Start reception**. This opens only the explicitly selected boards for sampled RF scans.

**Stop reception** keeps this survey and its results; **Resume reception** starts another acquisition interval using the same board and scan setup. Choose **New** before changing the selected boards, scan range/step. Paused time is unobserved.

The desktop spectrum-only gate always suppresses packet reception and classification, including stored profiles. Remembered USB identity/path pairs live in local preferences; recorded RAK surveys exclude them. Opening a saved session never connects its former receiver or GPS.

## Read the results

The live/Analyze chart shows the latest reading per board and frequency. Color expresses the fraction of histogram samples above **-87 dBm (uncalibrated)**, an exact four-decibel bin boundary. The table retains each reading's UTC timestamp, host operation interval, sample count and GPS availability. Frequencies are measured at different times. Missing readings are unknown; adjacent overlapping filters are not independent area coverage.

Use the HTML analysis report or frequency-summary CSV to summarize saved scans. Time and position reports preserve individual scan intervals and receiver endpoints rather than interpolating time buckets or spatial cells. GPS is the receiver's location, not the transmitter's. Saved history includes scans that are no longer in the bounded live table.

A scan-filter width is not a measurement of a transmitter's modem bandwidth. The sampled energy view cannot establish continuous airtime or protocol identity. Read [concentrator measurements and reports](../design/concentrator-measurements.md) for histogram, timestamp, storage and privacy semantics; older packet metadata may remain in historical files.

## Troubleshooting

- **Unavailable in this build:** inspect the CMake RAK worker status and platform requirements, then rebuild using the documented procedure.
- **Missing/ambiguous USB choice:** check the candidate count, refresh metadata and select the known board explicitly for each configured board slot. Choose New first if an existing survey locks the board settings. Close another program using it. Do not choose an unrelated STM32 device as a workaround.
- **No packets:** expected in this desktop scope. Packet reception and classification are disabled; sampled RF scans remain available.
- **USB fault/startup failure:** stop the session and preserve the error shown in Details. Reconnect only the affected concentrator before a deliberate retry; the app does not repeatedly restart a failing bridge.
- **No GPS:** inspect the separate GPS selection/fix state. Indoor reception can lack a fix; unlocated measurements remain unlocated.

The [source provenance](../../third_party/sx1302_hal/PROVENANCE.md) describes the bounded host-USB workaround and local receive-path changes. No new MCU firmware or persistent firmware flashing is required by this adapter. For help, use the [support playbook](support-playbook.md) or [OVMesh Discord](https://discord.gg/kwKhFamfaU). Do not publish private session files, keys or USB identities in a support report.

HTML reports summarize each board separately and plot sample exceedance by scan center. They expose the outer nominal filter edges, scan/sample counts and missing receiver fixes. A requested range can extend beyond the filters actually visited; elapsed scan bounds do not establish continuous reception. No samples above −87 dBm means only that the selected samples did not reach that threshold. Expand the retained histograms to inspect lower levels. Disabled packet profiles are omitted from spectrum-only reports.
