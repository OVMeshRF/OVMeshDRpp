# Data model and retention

Status: retention policy with default schema-6 compact recording and optional schema-5 detailed recording. Both preserve the joint activity introduced in schema 4 and waveform records from schema 5. The application records a usable range for arbitrary frequency/bin, elapsed-time and GPS-region analysis. [Implementation status](../engineering/implementation-status.md) separates implementation from validation. This document makes no new live-validation claim.

## Record families

| Record | Current fields or remaining target | Notes |
|---|---|---|
| Survey session and metrology | Session ID; configuration and gains; completion state; sample rate and usable span; software/schema version; FFT/window/normalization/threshold; optional antenna/receiver descriptions and notes. | Implemented. No keys or secret-bearing profile URLs. Mutable configuration epochs and a structured survey plan remain future work. |
| Observation coverage | Input/measurement totals; application dropped-sample counts; health checkpoints; known gap intervals with reason and sample counts when known. | Implemented. Source stalls have unknown missing counts; upstream loss is not inferred. Denominator for coverage-aware analysis. |
| Spectrum tile | Sample and UTC/elapsed bounds; first bin center and spacing; FFT/frame/bin counts; per-bin mean/peak powers; joint activity mask; spectral background; clipping/quality; receiver start/end fixes. | Approximately 20 ms phase-free activity records; compact mode shares up-to-one-second powers; see the [measurement specification](spectrum-measurement-record.md). |
| Spectrum summary | Per-frequency and legacy five-second aggregates; threshold and observed/active time. | Live convenience summaries; legacy five-second bin rows are omitted in Compact mode. Joint occupancy comes from schema-4 masks, not sums or averages of marginal occupancies. |
| Generic energy event | Sample and UTC/elapsed bounds; observed frequency edges; active duration; mean active-bin and peak-bin powers; quality; receiver start/end fixes. | Implemented connected-energy envelopes. No inferred packet identity, transmitter, modem bandwidth or opaque bytes. |
| Waveform observation | Observation ID; received center; inferred LoRa bandwidth/SF; first observed preamble time and delimiter time; up/down match fractions; contributing-subband count; requested-range and association flags; optional receiver fix. | Schema 5. Evidence of a compatible waveform, not a packet, protocol identity, transmitter identity or packet airtime. Cross-subband association updates an existing ID. |
| Discovery status and coverage | Enabled/method/finished/failed state; bounded fault text; accepted, rejected, channelized and abandoned input; queue drops/resets; result and gap-report overflows; observation count; per-subband processed/abandoned samples, source gaps and candidate/track limits; detailed gap intervals/reasons. | Schema 5. Independent of spectrum coverage. Input and subband-output sample units are explicit; counters and overlapping subbands must not be added to infer airtime. |
| Decoded message | Parsed authorized content; supported metadata; reported identities; validation/authentication status. | Only after the content eligibility checks pass. |
| Reception link | Existing receptions retain reported hop/relay hints; general energy-event/message links and duplicate-group associations remain targets. | Retain individual RF receptions; do not fabricate links from energy alone. |
| GPS fix | Source; fix time; position; accuracy/quality; receive time; validity. | Receiver track; sensitive location data. |
| Annotation | Session notes are implemented; structured event annotations and author/source relationships remain targets. | User interpretation must not replace measured evidence. No recommendation/candidate-ranking milestone is included. |

Each derived or parsed field must have an origin and relevant method/schema version. Missing and unsupported are distinct from zero. Decoded node-reported position must remain separate from receiver GPS.

Current sessions use one configuration, explicit sample/UTC/elapsed bounds, start/end GPS associations, record IDs and known coverage-gap intervals. Multiple immutable configuration epochs and persisted key-policy revisions remain future work. Unknown upstream loss cannot produce an exact missing-sample ledger.

## Allowed persistence boundary

In the normal application, RF samples and intermediate frame bytes exist only in bounded processing memory. The writer accepts allowlisted records and has no raw-payload escape field. Classification metadata must not hide packet bytes in arrays, hex/base64 strings, high-resolution symbol traces, or debugging attachments. Any opt-in development capture requires separate explicit permission and private storage; it does not broaden ordinary product retention.

The schema-4 through schema-6 binary fields have a specific measurement purpose: phase-free per-bin powers and one threshold bit per bin per complete FFT frame. Powers use little-endian signed int16 hundredths of a dB; masks use bounded byte RLE or a bounded literal-byte fallback. Tile dimensions are checked before expansion: at most 4096 bins and 128 frames. These fields contain neither sample phase nor raw IQ, ciphertext or packet bytes. CSV hex fields encode only these defined measurements and allow reconstruction of joint occupancy, not waveform replay or later payload decoding.

Retain successfully decrypted, validated content from configured authorized profiles when explicitly configured by the operator. Record authentication status honestly. Do not retain content on missing/wrong-key, malformed, ambiguous, or unsupported outcomes.

For undecoded traffic, retain only necessary RF measurements, categorical structural/validation facts, and approved reporting metadata. Exact identifiers from unowned traffic are not needed by default; adding any such field requires an explicit purpose/privacy review.

## Compact schema 6

New recordings default to Compact. `spectrum_tiles` retain every original approximately 20 ms activity tile, its full joint FFT bitmap, frequency grid, sample/UTC/elapsed bounds, background, clipping and quality. `power_blocks` share a frame-weighted linear per-bin mean and per-bin maximum across contiguous tiles spanning at most one second. Known discontinuities break a block. Tile references preserve the exact supporting power interval; readers flag `power_time_aggregated` and partial-support selections. Subsecond or geographically restricted power is an estimate over that wider support, while activity remains at original FFT resolution and threshold.

Tile GPS endpoints reference stable integer IDs for exact original fixes in `positions` instead of copying their fields. Coordinates, UTC, receipt time, altitude, source, satellites and HDOP are not rounded or smoothed. Identical fixes are deduplicated; distinct observations remain distinct. Missing fixes stay missing. Geographic reports default to 100-metre cells as a reporting choice, not a change to stored positions or a claimed accuracy radius.

Compact mode omits duplicate legacy five-second `window_bins` rows. Full-resolution occupancy is reconstructed from the joint masks. Generic energy events, waveform/discovery evidence, gaps, receiver settings and authorized content remain retained. No raw recording or new dependency is introduced. Mode changes apply only to new sessions; Detailed mode writes schema 5. Existing databases are never migrated or deleted. An older application that only understands schema 5 cannot open schema 6.

## Current schema-5 records and retained decoded projection

Detailed session files use schema 5. The schema-4 measurement definitions are unchanged: `spectrum_tiles`, `spectrum_events`, `coverage_gaps` and `survey_metrology` extend the existing typed tables. Reads validate schema layout, finite values, dimensions, encoding lengths, mask padding, timing and the session frequency grid. Detailed queries integrate power in linear units and union simultaneous activity across selected bins. Frequency selections expose the intersecting bins' actual edges; partial-tile power views are flagged. GPS rectangles use endpoint associations and exclude records without a usable endpoint fix. Bounded observation/event detail does not reduce full-query totals. The exact interpretation and limitations are in the [spectrum measurement record](spectrum-measurement-record.md).

Schema 5 adds `waveform_observations`, `discovery_status`, `discovery_bands` and `discovery_gaps`, plus the session's `discover_lora` flag. The method is recorded as `lora-preamble-v1`. Current inferred profiles are 125/250/500 kHz and SF7–12. Inferred modem bandwidth is distinct from a thresholded energy envelope or a regulatory occupied-bandwidth measurement. Match fractions are fit diagnostics, not calibrated confidence or authentication. No payload, ciphertext, IQ, symbol trace or key field is added.

A waveform row is inserted or updated by observation ID as overlapping subbands contribute evidence. Its first observed preamble-to-delimiter interval is not the packet duration and must not feed occupancy or airtime totals. Its receiver GPS fix is associated with the delimiter's acquisition time; absent or ineligible fixes remain absent. No transmitter position or movement is inferred. Recent readback is capped at 256 observations. Detailed analysis counts all matching rows while limiting displayed rows independently: the inferred frequency footprint must intersect the requested range, delimiter time must fall within the selected half-open time interval, and an enabled geographic filter excludes missing or out-of-bounds receiver fixes.

Discovery status is a cumulative checkpoint. Accepted input may still be queued and is not equivalent to processed coverage. Per-subband processed/abandoned counts use 2 MS/s output samples; source-gap counts use the receiver's input sample rate. Detailed gaps use half-open input-sample coordinates and a subband index (`-1` means all). Rejected input, abandoned work, result overflow, gap-report overflow and candidate/track limits remain separate. Invalid input ordering is a submission failure rather than additional elapsed RF time. These records do not establish exhaustive discovery, and spectrum measurements continue independently. The [experimental validation record](../engineering/quality-and-validation.md) distinguishes the successful narrow-span synthetic comparison from wider-span discovery overload and outstanding field validation.

New discovery tables require exact supported definitions. Read/write validation bounds numeric fields, sample coordinates, text, booleans and subbands; rejects nonfinite or inconsistent values; and exposes no opaque payload fallback. Historical files remain unchanged.

The decoder projection introduced in schema 3 is preserved without a new decoding claim. A valid Data envelope after an explicitly configured matching-key/channel attempt and passing PHY checks can contribute `evidence_port` and `evidence_signature_present`. If the application payload is unsupported, the reception is classified **possible Meshtastic**, with no authorized content or message/correlation identifiers retained. An accepted supported payload is classified **likely Meshtastic** and can carry an authorized typed projection. Neither case authenticates the sender; signature presence is never treated as signature verification.

Authorized projections add request/reply IDs, signature presence, and an explicit Routing wrapper variant (`request`, `reply`, or `error`). Direct traceroute payloads have no wrapper variant. An empty route request does not create a routing result or ACK. Forward route, return route, forward SNR and return SNR are four independent ordered lists, each bounded to 32 entries for new sessions. The existing `routes` table stores forward nodes; `route_details` stores the other typed sequences. No opaque payload column is introduced.

SNR values retain the full signed int32 wire domain in SQLite. The pinned firmware uses raw `-128` for unknown SNR and `0xffffffff` for an unknown route hop; the UI labels those markers and displays other SNR values divided by four as dB. It does not infer one-to-one route/SNR alignment. These are sender-reported observations, separate from receiver GPS and the SDR's own SNR estimate. The source interpretation is recorded in the [wire baseline](../research/meshtastic-wire-baseline.md).

Schemas 1–4 remain read-only without migration; no historical file is upgraded in place. Schema 4 retains detailed spectrum analysis but has no waveform/discovery records, which remain unavailable rather than being reconstructed. Schema 1 implies zero tuning correction. Schemas 1 and 2 retain their original readable forward-route limit of 64; fields introduced in schema 3 remain unavailable when reading those formats. Exports do not manufacture zero IDs, a missing-signature assertion or empty SNR lists. None of schemas 1–3 recorded the detailed tiles, generic event envelopes or joint masks needed for the new retrospective analysis. Their historical 25-percent measurement duty and level normalization remain distinct from schema 4.

Unencrypted content is not eligible for persistence merely because it is readable; a general unencrypted-content fallback is not implemented. Public framing recognition can still produce approved metadata.

## Desktop convenience settings

Versioned desktop preferences are separate from the survey schema. Format 5 stores recording/GPS switches and folder, GPS identity/baud, receiver source/frequency/rate/span/gains/amplifier, signed Offset, Compact/Detailed mode, discovery/decoding/Spectrum-only choices, typography and position-display mode. Ordinary startup opens a fresh workspace with RF stopped. New preferences enable recording and GPS, enable waveform discovery, arm authorized decoding with an empty keyring, and use Compact recording with zero Offset. Explicit opt-outs persist. GPS auto-connect is limited to the enabled uniquely recognized or remembered selected device.

Formats 1–4 remain readable. Existing fields and opt-outs survive migration; absent fields use documented defaults, and the next save writes format 5. These settings contain no keys, decoded content, coordinates or export privacy choices. Offset applies to the application profile and does not rewrite historical survey records. Every new recorded survey receives a new filename; restarting does not append to or overwrite an earlier session. Platform storage locations and private-file behavior are in [deployment](../operations/deployment.md).

Malformed preferences are left untouched. Live frequency summaries use current engine aggregates and do not create historical data when recording is disabled. Saved detailed queries use recorded spectrum measurements and, for schemas 5–6, waveform evidence; explicit refresh is required.

## Secrets, content, and export

Keep secret material outside session files. The current application holds keys in process memory; a future persistent key store requires a separately reviewed solution. A non-secret profile identifier may link a decoded event to the configured profile; never export the key or a key-bearing channel URL.

Parsed content may itself contain embedded bytes or sensitive application data. Define supported content types and export treatment; do not create an automatic raw-payload fallback for unknown schemas.

SQLite session storage is implemented and remains plaintext. Database encryption, retention durations, deletion controls, backup behavior, and operational disk budgets remain open. Application-level key isolation does not establish encryption of the entire survey database.

SQLite is embedded for local sessions. Acquisition resolution is distinct from saved-summary resolution; record both. Measurement metadata can still consume substantial storage, so measure capacity and make disk-pressure failures visible instead of silently discarding observations.

CSV and GeoJSON exports are implemented; the desktop offers a local CSV scope preview. CSV includes spectrum tile power arrays, bin summaries, lossless activity-frame/run rows, events, coverage and method metadata. These measurement records support reproducible joint occupancy. GeoJSON adds located RF observations from recorded tiles independently of plot limits, using raw all-bin busy time. Schema-5 CSV/GeoJSON also export all waveform rows and discovery status, subband coverage and gaps independently of display limits. Waveform exports label inferred settings explicitly and leave packet-airtime fields unpopulated. GeoJSON retains unlocated waveform and coverage records with null geometry; it does not manufacture a location. Coordinates use the selected decimal precision and describe receiver associations, not signal origins.

Adaptive full-interval display buckets and the optional receiver-center diagnostic are derived analysis results, not new schema-4 records. Each query uses a stable read snapshot and reports resolved time bounds, effective bucket width and coarsening. Raw any-bin totals and original bin measurements remain intact. Separate center/outside-center unions, actual guarded edges and bin counts support the comparison; no unguarded bins means unavailable, not zero. The guard is heuristic and cannot establish that excluded energy is an artifact or the frequencies are quiet. Neither the guard switch nor coarser display buckets rewrites records or replaces CSV/GeoJSON fields with the diagnostic values. Export semantics remain raw; byte-identical output across application versions is not asserted.

Authorized content, receiver coordinates and free-form antenna/receiver descriptions or survey notes have three independent opt-ins and are excluded by default. Hardware gain and measurement-method metadata remain in the default RF export. Free-form notes can contain private operational details; content inclusion alone does not include them. GeoJSON requires receiver-coordinate opt-in.

Metadata-only CSV may include qualifying envelope port/signature-presence evidence. Request/reply IDs, routing variant, authorized signature flag, both routes and both SNR arrays require content inclusion. Route node lists use semicolons; `snr_towards_db_x4` and `snr_back_db_x4` use JSON integer lists with raw values and sentinels preserved. Content opt-in never permits unsupported payload retention or export. See the [user guide](../user-guide.md#analyze-and-export-reports) for the current controls and privacy limits.

## Failure, recovery, and validation

The writer batches records in transactions and uses a cached tile insert statement. Normal engine checkpoints commit approximately once per second; each tile does not force a separate disk sync. A separate read-only connection can query committed live data through SQLite WAL. A crash can lose the uncommitted batch. Completion/interruption state remains explicit. Database journals, temporary files, caches, logs, backups, and crash artifacts are part of the retention review. Disk exhaustion must not silently discard results or trigger raw capture elsewhere.

No-raw-data design claims require verification of dependencies and OS memory/dump behavior. RAM-only processing alone does not prove that an operating system never pages or dumps memory.

Since undecoded bytes are discarded, later key entry or decoder improvements cannot recover historical payloads. Saved approved features can support limited analysis changes, but the original RF cannot be replayed. Reports must retain original classifier/method versions.
