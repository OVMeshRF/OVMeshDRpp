# Data model and retention

Status: SDR retention uses default schema-6 compact recording or optional schema-5 detailed recording. Both preserve the joint activity introduced in schema 4 and waveform records from schema 5. RAK5146 uses separate schema-7 sampled RSSI records, with no fabricated FFT occupancy. The application records a supplied range for frequency, elapsed-time and GPS-region analysis within each receiver's measurement limits. [Implementation status](../engineering/implementation-status.md) separates implementation from validation. This document makes no new live-validation claim.

## Record families

| Record | Current fields or remaining target | Notes |
|---|---|---|
| Survey session and metrology | Session ID; configuration and gains; completion state; sample rate and usable span; software/schema version; FFT/window/normalization/threshold; optional antenna/receiver descriptions and notes. | Implemented with immutable acquisition configurations. No keys or secret-bearing profile URLs. A structured survey plan remains future work. |
| Observation coverage | Input/measurement totals; application dropped-sample counts; health checkpoints; known gap intervals with reason and sample counts when known. | Implemented. Source stalls have unknown missing counts; upstream loss is not inferred. Denominator for coverage-aware analysis. |
| Spectrum tile | Sample and UTC/elapsed bounds; first bin center and spacing; FFT/frame/bin counts; per-bin mean/peak powers; joint activity mask; spectral background; clipping/quality; receiver start/end fixes. | Approximately 20 ms phase-free activity records; compact mode shares up-to-one-second powers; see the [measurement specification](spectrum-measurement-record.md). |
| Spectrum summary | Per-frequency and legacy five-second aggregates; threshold and observed/active time. | Live convenience summaries; legacy five-second bin rows are omitted in Compact mode. Joint occupancy comes from schema-4 masks, not sums or averages of marginal occupancies. |
| Generic energy event | Sample and UTC/elapsed bounds; observed frequency edges; active duration; mean active-bin and peak-bin powers; quality; receiver start/end fixes. | Implemented connected-energy envelopes. No inferred packet identity, transmitter, modem bandwidth or opaque bytes. |
| Waveform observation | Observation ID; received center; inferred LoRa bandwidth/SF; first observed preamble time and delimiter time; up/down match fractions; contributing-subband count; requested-range and association flags; optional receiver fix. | Schema 5. Evidence of a compatible waveform, not a packet, protocol identity, transmitter identity or packet airtime. Cross-subband association updates an existing ID. |
| Discovery status and coverage | Enabled/method/finished/failed state; bounded fault text; accepted, rejected, channelized and abandoned input; queue drops/resets; result and gap-report overflows; observation count; per-subband processed/abandoned samples, source gaps and candidate/track limits; detailed gap intervals/reasons. | Schema 5. Independent of spectrum coverage. Input and subband-output sample units are explicit; counters and overlapping subbands must not be added to infer airtime. |
| Packet classification | RF reception parameters, checks and status; minimal envelope port/signature-presence evidence. | No semantic message fields or sender identities. Envelope inference is unauthenticated and may be a false positive. |
| Reception identity | Locally assigned reception record ID. | Individual RF observations; no on-air packet IDs, hop/relay hints or semantic-message deduplication. |
| GPS fix | Source; fix time; position; accuracy/quality; receive time; validity. | Receiver track; sensitive location data. |
| Annotation | Session notes are implemented; structured event annotations and author/source relationships remain targets. | User interpretation must not replace measured evidence. No recommendation/candidate-ranking milestone is included. |

Each derived or parsed field must have an origin and relevant method/schema version. Missing and unsupported are distinct from zero. Only receiver position is retained; node-reported positions are not interpreted.

Current sessions retain each acquisition's configuration, explicit sample/UTC/elapsed bounds, start/end GPS associations, record IDs and known coverage-gap intervals. Stop/Resume appends an interval without clearing earlier results. Paused time remains unobserved, and changed settings never reinterpret earlier measurements. Persisted key-policy revisions remain future work. Unknown upstream loss cannot produce an exact missing-sample ledger.

## Acquisition intervals

New engine-created recordings add canonical `acquisition_segments` and `acquisition_lanes` tables to schemas 5, 6 and 7. The initial session configuration remains available; each later interval records its own center, rate, span, Offset, gains, threshold and supported processing settings. No keys or device identities are included. Readers validate interval ordering, configuration and measurement association, preserving exact frequency edges rather than resampling different grids. Save copy preserves this extension; older readers may reject it despite recognizing the numeric schema. Do not remove its tables or edit version numbers to force compatibility. Historical recordings remain unchanged.

Same-source SDR adjustments are allowed after Stop and apply on Resume. Receiver-type, recording destination/detail-mode and RAK board/scan/packet-setting changes require New. Saved historical sessions open read-only. Full-range analysis includes all recorded acquisition ranges; CSV and HTML reports distinguish configurations so changed sensitivities and thresholds are visible. Discovery health checkpoints describe only the latest acquisition. Earlier waveform records remain available, but earlier discovery coverage is unavailable; global discovery-gap sample counters must not be converted to elapsed time using a single rate after rate changes.

## Allowed persistence boundary

In the normal application, RF samples and intermediate frame bytes exist only in bounded processing memory. The writer accepts allowlisted records and has no raw-payload escape field. Classification metadata must not hide packet bytes in arrays, hex/base64 strings, high-resolution symbol traces, or debugging attachments. Any opt-in development capture requires separate explicit permission and private storage; it does not broaden ordinary product retention.

The schema-4 through schema-6 binary fields have a specific measurement purpose: phase-free per-bin powers and one threshold bit per bin per complete FFT frame. Powers use little-endian signed int16 hundredths of a dB; masks use bounded byte RLE or a bounded literal-byte fallback. Tile dimensions are checked before expansion: at most 4096 bins and 128 frames. These fields contain neither sample phase nor raw IQ, ciphertext or packet bytes. CSV hex fields encode only these defined measurements and allow reconstruction of joint occupancy, not waveform replay or later payload decoding.

Retain no semantic message contents, sender/node identities, packet/request/reply IDs, telemetry or routes. A bounded envelope classifier can contribute only port and signature presence after eligible explicit-key processing. Its inference is unauthenticated and may be a false positive.

For undecoded traffic, retain only necessary RF measurements, categorical structural/validation facts, and approved reporting metadata. Exact identifiers from unowned traffic are not needed by default; adding any such field requires an explicit purpose/privacy review.

## Concentrator schema 7

RAK5146 recordings use source discriminator 3 and a versioned extension for board receive profiles, completed 33-bin RSSI histograms, packet RSSI/board timestamps and health counters. The fixed 2,000-sample histograms use a nominal 234,300 Hz filter and uncalibrated vendor power offset; sample exceedance is not continuous occupancy or packet airtime. Host scan intervals and optional full-precision receiver-fix references are retained. USB device paths and identities are excluded from session storage.

The FFT tables/metrology remain empty for this source. Detailed CSV, GeoJSON and concentrator reports retain the measurement's method and limitations. Hardware-configured packet bandwidth stays distinct from measured transmitter width. Existing SDR files are read without migration. See [concentrator measurements](concentrator-measurements.md) for exact encoding, validation, threshold, privacy and report-selection semantics.

## Compact schema 6

New recordings default to Compact. `spectrum_tiles` retain every original approximately 20 ms activity tile, its full joint FFT bitmap, frequency grid, sample/UTC/elapsed bounds, background, clipping and quality. `power_blocks` share a frame-weighted linear per-bin mean and per-bin maximum across contiguous tiles spanning at most one second. Known discontinuities break a block. Tile references preserve the exact supporting power interval; readers flag `power_time_aggregated` and partial-support selections. Subsecond or geographically restricted power is an estimate over that wider support, while activity remains at original FFT resolution and threshold.

Tile GPS endpoints reference stable integer IDs for exact original fixes in `positions` instead of copying their fields. Coordinates, UTC, receipt time, altitude, source, satellites and HDOP are not rounded or smoothed. Identical fixes are deduplicated; distinct observations remain distinct. Missing fixes stay missing. Geographic reports default to 100-metre cells as a reporting choice, not a change to stored positions or a claimed accuracy radius.

Compact mode omits duplicate legacy five-second `window_bins` rows. Full-resolution occupancy is reconstructed from the joint masks. Generic energy events, waveform/discovery evidence, gaps, receiver settings and classification evidence remain retained. No raw recording or new dependency is introduced. Mode changes apply only to new sessions; Detailed mode writes schema 5. Existing databases are never migrated or deleted. An older application that only understands schema 5 cannot open schema 6.

## Current schema-5 records and classification projection

Detailed session files use schema 5. The schema-4 measurement definitions are unchanged: `spectrum_tiles`, `spectrum_events`, `coverage_gaps` and `survey_metrology` extend the existing typed tables. Reads validate schema layout, finite values, dimensions, encoding lengths, mask padding, timing and the applicable acquisition frequency grid. Detailed queries integrate power in linear units and union simultaneous activity across selected bins. Frequency selections expose the intersecting bins' actual edges; partial-tile power views are flagged. GPS rectangles use endpoint associations and exclude records without a usable endpoint fix. Bounded observation/event detail does not reduce full-query totals. The exact interpretation and limitations are in the [spectrum measurement record](spectrum-measurement-record.md).

Schema 5 adds `waveform_observations`, `discovery_status`, `discovery_bands` and `discovery_gaps`, plus the session's `discover_lora` flag. Earlier recordings use `lora-preamble-v1` for 125/250/500 kHz and SF7–12. New recordings use `lora-preamble-v2`: 62.5/125/250/500 kHz at SF7–12 plus 15.625 kHz at SF7–10. Readers accept both methods; older readers may reject v2 rather than silently assume its narrower search. Inferred modem bandwidth is distinct from a thresholded energy envelope or a regulatory occupied-bandwidth measurement. Match fractions are fit diagnostics, not calibrated confidence or authentication. No payload, ciphertext, IQ, symbol trace or key field is added.

A waveform row is inserted or updated by observation ID as overlapping subbands contribute evidence. Its first observed preamble-to-delimiter interval is not the packet duration and must not feed occupancy or airtime totals. Its receiver GPS fix is associated with the delimiter's acquisition time; absent or ineligible fixes remain absent. No transmitter position or movement is inferred. Recent readback is capped at 256 observations. Detailed analysis counts all matching rows while limiting displayed rows independently: the inferred frequency footprint must intersect the requested range, delimiter time must fall within the selected half-open time interval, and an enabled geographic filter excludes missing or out-of-bounds receiver fixes.

Discovery status is a cumulative checkpoint within the latest acquisition. Accepted input may still be queued and is not equivalent to processed coverage. Per-subband processed/abandoned counts use 2 MS/s output samples; source-gap counts use the receiver's input sample rate. Detailed gaps use half-open input-sample coordinates and a subband index (`-1` means all). Rejected input, abandoned work, result overflow, gap-report overflow and candidate/track limits remain separate. Invalid input ordering is a submission failure rather than additional elapsed RF time. These records do not establish exhaustive discovery, and spectrum measurements continue independently. The [experimental validation record](../engineering/quality-and-validation.md) distinguishes the successful narrow-span synthetic comparison from wider-span discovery overload and outstanding field validation.

New discovery tables require exact supported definitions. Read/write validation bounds numeric fields, sample coordinates, text, booleans and subbands; rejects nonfinite or inconsistent values; and exposes no opaque payload fallback. Historical files remain unchanged.

Receptions retain RF/GPS measurements, categorical status and optional `evidence_port` / `evidence_signature_present`. A plausible Data envelope after required PHY checks and an explicitly configured key attempt supports **likely Meshtastic**, without parsing the inner application message. Every authentication label remains **not authenticated**; signature presence is not verification.

Schemas 1–7 remain readable through an allowlisted metadata projection without migrating or rewriting their source. Old semantic reception columns and route tables are never loaded into product records, displays, searches or exports. Schemas 1–3 still lack detailed joint-activity history; their original timing/duty and normalization remain distinct. Missing waveform measurements in older files stay unavailable.

New files retain the supported schema-5/6/7 shapes and add a validated `metadata_policy` singleton with `metadata-only-v1`. Reserved legacy semantic columns remain NULL and route tables remain empty. New-policy **Save copy** reconstructs a fresh private database from allowed records; it does not copy source database pages or free-page remnants. Save copy rejects unmarked historical files before creating a destination. The original may still contain older private contents; metadata export is available without changing it.

## Desktop convenience settings

Versioned desktop preferences are separate from the survey schema. Format 8 stores recording/GPS switches and folder, GPS identity/baud, receiver source/frequency/rate/span, HackRF gains/amplifier, RTL tuner gain and automatic-gain mode, signed Offset, Compact/Detailed mode, discovery/classification/Spectrum-only choices, typography and position-display mode. It retains the RAK source, one or two explicitly selected local USB path/identity pairs, per-board packet profiles, and scan/classification settings, and adds the Meshtastic public-default-key switch. These USB identities remain local preferences and are excluded from RAK survey records. Ordinary startup opens a fresh workspace with RF stopped. New preferences enable recording, GPS, waveform discovery and the visible public-default-key classification option, with no private keys, Compact recording and zero Offset. Explicit opt-outs persist. GPS auto-connect is limited to the enabled uniquely recognized or remembered selected device.

Preference formats 1–7 remain readable. Existing fields and opt-outs survive migration; absent fields use documented defaults, and the next save writes format 8. These settings contain no private keys, decoded content, coordinates or export privacy choices; the public-key choice is a boolean. Offset applies to the receiver setup, resets when switching receiver type, and does not rewrite historical survey records. Every new recorded survey receives a new filename. Stop/Resume appends to the current survey, while restarting the application opens a fresh workspace and never appends to an earlier file. Platform storage locations and private-file behavior are in [deployment](../operations/deployment.md).

Malformed preferences are left untouched. Live frequency summaries use current engine aggregates and do not create historical data when recording is disabled. Saved detailed queries use recorded spectrum measurements and, for schemas 5–6, waveform evidence; explicit refresh is required.

## Secrets and export

Keep secret material outside session files. The current application holds keys in process memory; a future persistent key store requires a separately reviewed solution. Configured keys do not leave the classifier; never export a key or key-bearing channel URL.

Inner application payloads are skipped during bounded envelope parsing. No semantic payload objects, content strings or opaque fallback fields are produced.

SQLite session storage is implemented and remains plaintext. Database encryption, retention durations, deletion controls, backup behavior, and operational disk budgets remain open. Application-level key isolation does not establish encryption of the entire survey database.

SQLite is embedded for local sessions. Acquisition resolution is distinct from saved-summary resolution; record both. Measurement metadata can still consume substantial storage, so measure capacity and make disk-pressure failures visible instead of silently discarding observations.

CSV and GeoJSON exports are implemented; the desktop offers a local CSV scope preview. CSV includes spectrum tile power arrays, bin summaries, lossless activity-frame/run rows, events, coverage and method metadata. These measurement records support reproducible joint occupancy. GeoJSON adds located RF observations from recorded tiles independently of plot limits, using raw all-bin busy time. Schema-5 CSV/GeoJSON also export all waveform rows and discovery status, subband coverage and gaps independently of display limits. Waveform exports label inferred settings explicitly and leave packet-airtime fields unpopulated. GeoJSON retains unlocated waveform and coverage records with null geometry; it does not manufacture a location. Coordinates use the selected decimal precision and describe receiver associations, not signal origins.

Adaptive full-interval display buckets and the optional receiver-center diagnostic are derived analysis results, not new schema-4 records. Each query uses a stable read snapshot and reports resolved time bounds, effective bucket width and coarsening. Raw any-bin totals and original bin measurements remain intact. Separate center/outside-center unions, actual guarded edges and bin counts support the comparison; no unguarded bins means unavailable, not zero. The guard is heuristic and cannot establish that excluded energy is an artifact or the frequencies are quiet. Neither the guard switch nor coarser display buckets rewrites records or replaces CSV/GeoJSON fields with the diagnostic values. Export semantics remain raw; byte-identical output across application versions is not asserted.

Receiver coordinates and free-form antenna/receiver descriptions or survey notes are independent opt-ins and excluded by default. Hardware gains and measurement-method metadata remain in default RF exports. Notes may contain private operational details. GeoJSON requires receiver-coordinate opt-in.

CSV archives can include qualifying envelope port/signature-presence evidence. No report has content inclusion or message-content columns. The removed content CLI flags fail explicitly. See the [user guide](../user-guide.md#analyze-and-export-reports).

## Failure, recovery, and validation

The writer batches records in transactions and uses a cached tile insert statement. Normal engine checkpoints commit approximately once per second; each tile does not force a separate disk sync. A separate read-only connection can query committed live data through SQLite WAL. A crash can lose the uncommitted batch. Completion/interruption state remains explicit. Database journals, temporary files, caches, logs, backups, and crash artifacts are part of the retention review. Disk exhaustion must not silently discard results or trigger raw capture elsewhere.

No-raw-data design claims require verification of dependencies and OS memory/dump behavior. RAM-only processing alone does not prove that an operating system never pages or dumps memory.

Since undecoded bytes are discarded, later key entry or decoder improvements cannot recover historical payloads. Saved approved features can support limited analysis changes, but the original RF cannot be replayed. Reports must retain original classifier/method versions.

## RTL receiver provenance extension

New RTL sessions use the existing detailed/compact measurement formats (5/6) with an explicit receiver extension: `session.synthetic=2` identifies real RTL input, and a validated singleton `receiver_setup` table records `hardware=rtl_sdr`, applied tuner gain in tenths of dB, and automatic-gain mode. Sources 0/1 retain the prior HackRF/synthetic representation without this table. Older applications reject the RTL extension rather than silently treating it as HackRF. The new reader preserves existing formats 1–6 without rewriting them. Automatic gain does not imply a known instantaneous applied gain; exports leave the fixed gain blank in this mode. Serials are not added to survey files.

## Automatic PHY metadata extension

New schema-5/6/7 files include a strictly validated version-1 `automatic_decoder` table. Each acquisition records availability, enabled/finished state and bounded numeric counts for candidates, starts/completions, CRC-valid/classified frames, history misses, capacity limits, duplicate/manual exclusions, unsupported/out-of-range candidates, timeouts, resets, abandoned decoders and frame overflows. Active decoder/history sizes are checkpoint values. No keys, bytes, addresses or message content are added.

Older files without this extension remain readable with decoder setup/diagnostics explicitly unavailable. Save copy preserves that unknown state. The snapshot/UI/report counters describe the latest acquisition; raw CSV/GeoJSON export includes a separate status row for every acquisition. Session reception totals can span multiple acquisitions and must not be compared directly to latest-acquisition decoder counts. Detailed live PHY subcounters are not persisted.

Automatic frame receptions retain the existing permitted RF/CRC/classification metadata and acquisition-time receiver GPS association. CRC-failed frame bytes are erased before handoff; CRC-valid bytes are transiently classified and erased. Bounded IQ replay remains memory-only and is cleared on resets/destruction. This is not a raw-recording feature and does not change ADR-0010.
