# RTL-SDR driver intake

The direct receive adapter uses selected **Osmocom librtlsdr 2.0.3** sources at revision `797f8143266d983c56d8f35d2d442527529dd8a5` from the [official project mirror](https://github.com/osmocom/rtl-sdr/tree/797f8143266d983c56d8f35d2d442527529dd8a5). The library supports RTL2832U tuner devices, including upstream's Blog V4 handling; individual models still need validation. Source and archive hashes are recorded in [the source manifest](../../third_party/rtlsdr-source.json). The archive was retrieved over HTTPS; no independent publisher signature was verified. Hashes detect subsequent drift, not upstream compromise.

Only six library/tuner C implementations, their headers, and original copyright/license texts are included. Our CMake compiles them directly and links the reviewed local shared libusb 1.0.30 used by the HackRF adapter; see [USB intake](usb-intake.md). The RTL build does not execute upstream RTL build scripts, install system drivers, detach kernel drivers, install udev rules, compile `rtl_tcp` or other command-line utilities, or fetch anything during configuration/build. USB dependency preparation is a separate explicit helper step. The application uses no network receiver. This avoids a radio framework or Python runtime dependency.

Static review covered the selected library's includes, allocation and USB paths, public API, gain tables, tuner setup, and asynchronous cancellation. The selected code has no subprocess, network socket, dynamic-library loader or file-based updater path. This is a bounded intake review, not a guarantee of absence of vulnerabilities. libusb and the platform USB stack remain dependencies requiring updates and distribution review.

## Local hardening

The async allocation path originally used unchecked pointer allocations and ignored an allocation-error return. The local patch checks each allocation, releases partial buffers, restores the inactive state on failure, and rejects lengths that overflow libusb's signed transfer length. It also clears freed zero-copy fallback pointers; zero-copy is disabled in this build. `tests/test_rtlsdr_allocation.c` injects allocation failures without opening USB and checks cleanup, no submitted transfers, and retry behavior. The R820T/R828D wrapper also rejects a tuning call that reports success without PLL lock; a mocked locked/unlocked/error test covers both tuners. This prevents uncertain tuning from becoming a valid survey. Original hashes and patched hashes are retained separately in the provenance and integrity manifests.

The app bounds its input queue and transfer sizes, converts unsigned offset-binary IQ explicitly, and joins the async reader before closing the device. Stop retries cancellation through upstream's reader-start race. Device access occurs only on an explicit receive action or an explicitly authorized CLI mode; capability checks do not open USB. Multiple receivers require an exact serial selection. Bias tee, digital AGC, direct sampling and test mode are disabled; manual tuner gain is the survey default. Automatic tuner gain is optional and recorded because it limits comparisons of received levels.
